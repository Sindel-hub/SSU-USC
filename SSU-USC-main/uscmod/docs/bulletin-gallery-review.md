# Bulletin attachments and review

The existing announcement workflow and officer permission checks remain authoritative. The Create Announcement form accepts survey URLs in its content; the dedicated survey field is removed. Existing `surveyId` records still render their original Take Survey links. The Needs Assessment service is unchanged.

Images are selected cumulatively, previewed and removable before saving. JPEG, PNG and WebP inputs remain limited to 5 MB each, rasterized proportionally to at most 1200 pixels, and limited to 400,000 encoded characters per stored image. There is no application image-count cap. Each image uploads separately through the authenticated management API, avoiding the request and Firestore document limits for an inline image array. Existing platform storage/request/transaction quotas still apply.

New `announcement_images` documents are private under the existing default-deny Firestore rules. Uploads require draft permission. Draft attachment references are checked against their author's ownership; private image reads require authorized draft/review/publish access and membership in that draft. Image identifiers are immutable. Published records expose ordered image URLs through the existing announcement-image API, which verifies current publication and membership. Legacy single-image records continue to work. Removed or cancelled selections are never attached to a published post; unreferenced private uploads are retained, not exposed publicly.

The shared gallery renders one, two, three, or four visible images; additional images are available through the +N tile and the full-screen viewer. Keyboard arrows, previous/next buttons, mobile swipes, Escape and the close button navigate or dismiss the viewer. Full-size viewing uses object-fit: contain. The gallery is connected to the officer bulletin, officer overview, student dashboard/bulletin and public landing page. Content links are constructed from text nodes, limited to HTTP(S), with opener protection. They do not interpret HTML from announcements.

Review Announcements opens an independent scrolling dialog. Its badge comes from all authorized database records, independent of list pagination: submitted posts reviewable by the officer plus Ready posts they can publish. Own submissions count only when existing self-approval permission permits review. Drafts and revision requests remain editable in the dialog but do not inflate the pending counter. Local actions update the badge immediately; other users' changes refresh automatically every 15 seconds while the page is visible, and when the dialog opens or the tab becomes visible. Opening the dialog never marks a record processed.

Facebook cross-posting retains its current delivery/retry/reconciliation behavior. The first image remains the Facebook cover; all attachments are available on the SSU-USC announcement. This change does not add Facebook album publishing.

Deploy frontend and Node API changes together through the reviewed Vercel PR workflow. No rules migration, Supabase deployment, production record rewrite, or manual data conversion is needed. Live Facebook delivery, production Firebase access and a Vercel deployment were not performed during local validation.

Validation: `npm test`; `node tests/browser/announcement-review.cjs`. The browser test uses isolated Auth/Firestore doubles, actual HTTP handlers, image upload/serving and synthetic images. It covers cumulative selection/removal, review and publication, the badge, image grids/viewer, content links, legacy survey links and mobile layout. VM-based carousel/media/formatting test fixtures include the new renderer dependency without changing their assertions.
