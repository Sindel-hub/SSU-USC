# One response per student

Existing external survey URL remains unchanged. Students sign in with their existing account; the login page returns students to the validated survey ID. Both survey read/status and submit endpoints require a verified active student role. Department is taken from the trusted profile, not from the client. Duplicate prevention is by normalized student ID (preserving leading zeros) per survey, not UID or device. A private scoped digest is stored in a server-only marker, not in the officer response. Marker, independently random response ID, and response count are created atomically. Officers get an explicit allowlist of department, answers, and submission time; the response cursor is a random response identifier unrelated to the marker. Privacy is from officers, not an absolute anonymity guarantee against trusted infrastructure administrators or identifying content volunteered by respondents. No new secret or database migration required. Previous anonymous responses cannot be attributed retroactively; start a fresh survey to enforce one response per student across the entire collection period.

Verify in isolated staging before merging: signed-out access, student login return, authorized departments, duplicate requests and concurrent requests, different accounts including same student ID after account replacement, closed survey, failed validation, officer response JSON and CSV privacy, direct database access denial. Existing browser fixture predates the dedicated editor and needs updating; no browser integration test is claimed.
